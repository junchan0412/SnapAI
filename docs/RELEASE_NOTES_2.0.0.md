# SnapAI 2.0.0

SnapAI 2.0.0 重构了核心模块、请求生命周期与存储链路，并重新设计了主要工作界面。旧版配置、快捷键和历史记录继续兼容。

## 使用体验

- 设置改为分组工作区，供应商、模型与路由配置有更清晰的层级；保存失败会保留修改并提供重试。
- 快捷提问采用可扩展的多行编辑区，支持键盘发送、换行、图片附件与中文输入法组合输入；取消发送前确认会保留草稿。
- 结果窗口以正文为中心，原文默认折叠，模型、路由、耗时和诊断按需查看。手动滚动时暂停自动跟随。
- 历史记录采用列表与阅读双栏布局，支持 Markdown 阅读、搜索、收藏、标签、筛选、导出和继续提问。Command-F 可聚焦搜索。
- 命令面板可调整大小，首次引导、浅深色和按钮反馈保持一致。

## 性能与架构

- 核心逻辑统一为真正的 `SnapAILogic` 模块，移除 App 与逻辑模块之间的全部 symlink 源码镜像及重复自动化类型；App 通过 Swift `package` 访问内部 API。
- SQLite 复用连接与预编译语句，增加日期索引；收藏操作不再重建全文索引。
- 设置保存按变化处理历史数据，并避免重复写入相同配置。
- Markdown 解析只保留当前任务与最新待处理文本，502 次连续刷新测试仅触发 2 次解析。
- 打字机在等待 token 和思考阶段停止空转，`<think>` 解析使用增量游标。

在 Apple M4 / 16 GB、macOS 27 的合成负载中，最后一轮 500 条历史记录对照中，批量写入中位数从 144.990 ms 降至 36.849 ms；30 次读取从 400.870 ms 降至 131.495 ms；50 次收藏更新从 895.471 ms 降至 6.013 ms。以上是本机特定负载，不代表所有使用场景。方法、原始样本与复现入口见 [重构验证报告](REFACTOR_REPORT_2.0.0.md)。

## 稳定性与数据保护

- SSE 按字节和事件边界解析，正确处理 UTF-8、CRLF、多行 data、提前断流、空响应、输出上限与服务错误；不再把不完整响应标为成功。
- 切换动作、重试、取消或释放请求时，旧回调无法写入新结果。
- 历史迁移、索引迁移和写入使用明确失败状态与事务；失败时保留可恢复数据。
- 密钥文件原子替换，串行处理并发读写；master key 丢失时保留既有密文。
- iCloud 失败保留待同步状态，启动后可继续同步。
- 关闭后立即重新打开面板，不会被旧动画回调关闭；Escape 优先关闭请求详情，输入法组字期间不抢占按键。
- 历史保存失败会提示先复制或导出；关闭历史记录时不会误报保存失败。退出前保存未提交的设置。

## 安装与更新

- 需要 macOS 14 或更高版本，发布包为 Apple Silicon 构建。
- 构建统一由 SwiftPM 驱动，并验证 App 与 updater 的实际最低系统版本。修正了 1.6.75 二进制实际要求 macOS 27、与声明不一致的问题。
- 继续使用原来的 bundle id、稳定签名证书和 manifest 公钥，支持应用内升级。
- 提供 ZIP、签名 manifest、签名文件与 SBOM。应用仍采用自签名分发，尚无 Apple notarization；首次安装步骤见 README。
