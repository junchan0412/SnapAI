# SnapAI 后续路线图

更新：2026-10-25。依据 [当前检查报告](../reports/PROJECT_HEALTH_2026-10-25.md) 和 [2.1.0 验收记录](../reports/RELEASE_ACCEPTANCE_2.1.0.md)。这是后续建议与验收清单，条目均未因本次文档整理而自动完成。阶段按依赖顺序安排，不作未经排期的日期承诺。

## P0：可靠性和发布可信度

| 待办 | 交付物 / 验收标准 |
| --- | --- |
| 跨应用取词与写回补验 | 复用自有 fixture，在 TextEdit、Word、浏览器、Electron 各记录 AX/复制兜底、焦点漂移、源文变化、剪贴板竞争和撤销；成功、安全拒绝、环境阻塞分别统计，保留原始证据；任何误写先修复 |
| Shortcuts 完整链路 | 从系统发现 SnapAI 动作，执行正文返回 → 下游文本处理；验证隐私确认、超时、取消及结构化错误；使用隔离配置和固定无敏感样本 |
| 低版本与辅助功能 | macOS 14/15 记录启动、窗口、材质回退、截图权限、更新窗口；VoiceOver 与纯键盘走查主路径、裁剪数值控件和表格/代码阅读；缺设备就明确标为未验收 |
| iCloud 配置同步核验 | 先核对实际发布 bundle entitlement 和账户能力，再双设备检验配置同步、冲突与失败恢复；若链路不可用，应在 UI/文档说明；历史、会话及 Key 不扩大同步范围 |
| 编译 warning 收尾 | 处理报告列出的两类 warning，保持 AX 类型校验和 OCR 取消测试有效；当前 language mode 构建与现有相关回归通过；Swift 6 迁移另行评估 |

本阶段完成标准：高风险写回场景均有可解释结果；发布说明与实机范围一致；未知与未测项目有明确记录。不得把 runner 通过冒充系统快捷键、Shortcuts 或任意控件均通过。

## P1：性能、阅读和质量

| 待办 | 交付物 / 验收标准 |
| --- | --- |
| 建立端到端性能基线 | 同设备、同配置，至少 30 样本；记录快捷键 → 可输入、键入 → 搜索结果、生成完成 → 排版完成；保存源码/build/fixture hash、P50/P95 与失败样本 |
| 长文和图片资源验证 | 10k/40k/100k 混合正文，表格与代码横滚、中段阅读位置；大图添加/裁剪/删除/恢复和在途取消；固定 5/15/30 分钟采样，区分 RSS、footprint 和 peak |
| 帧耗时归属 | 录制时证明进程 → surface → frame 的关联，保留可复核证据，再报告 60/120 Hz 下的帧预算；无目标设备则不作稳定 FPS 承诺 |
| 历史语义搜索 | 使用唯一文本与不同查询，覆盖首次和重复查询、50/200/500 条历史；检查先显示词法结果、取消旧查询与最终结果一致性；按新基线再选择优化点 |
| 固定任务质量 | 在明确供应商、模型和费用范围后扩充翻译/润色/总结/代码/截图样本；保真、格式、截断与请求成功分开评分，保留失败，不以 agent 自评代替双人盲评 |
| 本地化收尾 | 盘点主路径硬编码中文，补齐资源并走查英文长文案、空状态与错误；保持快捷键、模型名和供应商术语一致 |

性能阈值在重复基线稳定后设定；CI 可继续做构建/行为 smoke，固定设备承担数值回归，避免共享 runner 的负载波动产生误报。

## P2：按需求证据选择下一项产品能力

| 候选 | 进入条件 |
| --- | --- |
| 应用/项目配置 | 有反复切换动作、模型和上下文的真实任务证据，先定义匹配规则、覆盖优先级和可见反馈 |
| 逐段接受改写 | 已确认长文改写的使用频率，先解决 source range、源文变更、富文本与撤销语义 |
| 更强会话管理 | 当前恢复、分支、摘要压缩的使用反馈显示具体障碍，再选择管理、搜索或导出改进 |
| 文件检索与引用 | 当前轮次明确排除；只有用户重新确认需求后，才评估权限、引用可追溯性、存储和成本 |

## 持续维护

- 每次行为改动同步对应版本说明；功能是否实现、自动检查是否通过、实机是否验收分开记录。
- 文档只在分类目录新增，过程日志按时间归档；README 和文档索引只保留当前入口。
- 优先使用现有 request session、coordinator 和测试 fixture；不为尚未验证的能力新增依赖或框架。
- 后续测试定位改进可从拆分聚合 XCTest 入手，按现有模块逐步做，避免一次性重写全部测试。
